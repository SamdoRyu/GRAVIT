# Review PR

리뷰는 코드 스타일 취향보다 defect risk를 우선한다.

우선순위:
1. 이슈의 요구사항 ID 수용 기준 불충족 — PR의 "관련 요구사항" ID가 이슈와 같은지, 그 ID의 수용 기준을 diff가 채우는지
2. 공통 계약 불일치 — 경로 · DTO 필드 · enum 값 · 에러 코드 · 상태 코드가 `docs/CONTRACTS_API.md`(PR의 기준 계약 커밋)와 같은지. 계약에 없는 것을 코드가 먼저 만들었는지
3. 기능 regression
4. 보안/권한 — 세션 · CSRF · 사무실 접근 검사 · IDOR(다른 사무실 ID로 접근)
5. 데이터 손실/잘못된 상태
6. race condition / async 오류
7. error handling
8. 타입 불일치
9. 테스트 누락
10. 유지보수성

GRAVIT 원칙 점검 (위반이면 blocker):
- GitHub 쓰기 호출 없음 — GitHub 원본(이슈 · PR · 코멘트 · 라벨 등)을 바꾸는 GitHub API 호출이 없다 (CON-02). OAuth 코드 교환 · 설치 토큰 발급 같은 인증 요청과 앱 서버 자체 API의 쓰기는 위반이 아니다. GitHub API 호출은 백엔드 `github` 패키지 안에만 있다.
- 사무실 격리 — 사무실 단위 데이터를 사무실 조건 없이 조회하지 않는다. 권한 없는 사무실은 `404`, 역할 위반은 `403 forbidden_role`.
- 사람별 합계·순위 필드 없음 — 응답 DTO와 화면에 사람별 평가 합계, 활동량 합계, 순위, 사람 간 비교가 없다 (FR-FLOW-06, FR-LRN-09). 개인 지표는 본인과 강사 요청에만 나간다 (NFR-06). 평가자 · 동료 피드백 작성자 식별 값이 응답에 없다(익명성).
- 강사 쓰기 제한 — 강사(ROLE-04)의 쓰기는 학생이 요청한 건(도움 요청 답변 · 꼬리질문 · 결정 피드백)과 컨벤션 라이브러리에만 열린다. 그 밖의 강사 쓰기는 API에서 `forbidden_role`로 막혀 있다 (FR-AUTH-08). 강사 의견이 결정 · 평가 · 안건 · 도움 요청 상태를 바꾸지 않는다 (SP3).
- 심사용 계정 — 시연 사무실에만 접근하고, 같은 세션 · CSRF · 인가 검사를 거친다.
- Entity를 응답으로 바로 내보내지 않는다. 스키마 변경은 Flyway 마이그레이션으로만 한다.

각 finding은:
- Severity: blocker / major / minor
- 위치
- 문제
- 왜 문제인지
- 최소 수정 제안

문제가 없으면 억지 finding을 만들지 않는다.
마지막에 "merge 가능 / 수정 후 가능 / 현재 merge 비권장" 중 하나로 결론낸다.
